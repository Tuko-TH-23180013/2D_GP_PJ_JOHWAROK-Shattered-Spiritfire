# 조화록 — 1지역 점진적 개발 계획

작성일: 2026-11-09 / Python · Pico2D / 1인 개발

> 목표: 각 단계가 끝날 때마다 실행 가능한 게임을 남긴다. 사각형으로 핵심 동작을 완성한 뒤, 전투·지역·그래픽을 차례로 붙인다.

## 1. 최종 목표와 범위

최종 제출은 **2026-12-08(화)**. **12-03 기능 동결**, **12-04~07 오류 수정 및 제출 검증**을 기준으로 한다. 아래 날짜는 확정 마감에 맞춘 권장 작업 일정이며, 실제 작업 속도에 따라 앞 단계의 작업량을 조정한다.

필수 범위는 장승마을 1지역, 기본·거대 방망이, 일반 몬스터 최소 1종, 보스 1종과 패턴 2개, 콤보·대시·무기 전환·스태거, 체크포인트·사망 재시작, 기본 UI다. 보스는 최근 축소 범위의 **오래된 도깨비**를 기준으로 가칭을 사용한다. 보스 외형이 달라져도 같은 구현 구조를 사용한다.

중간 보스와 최종 보스를 각각 만드는 기존 확장 구상은 이번 최소 범위에서 제외한다. 혼불 방망이, 능력 A/S, Shift 특수 대시, 2~4지역, 히든 보스는 후속 확장으로 둔다.

## 2. 개발 환경과 작업 방식

### 실행 환경

- VS Code에서 프로젝트 폴더를 열고 전용 Python 가상환경 `.venv`를 만든다.
- 수업에서 사용하는 Python/Pico2D 조합을 먼저 검증한다. 검증한 버전을 README에 기록하고, 제출 직전까지 유지한다.
- 실제 설치한 의존성을 `requirements.txt`에 기록한다. 다른 컴퓨터에서 같은 환경으로 실행되는지 마지막 주에 확인한다.
- 모든 이미지·음원 경로는 소스 파일 위치를 기준으로 계산한다. 개인 컴퓨터의 절대 경로는 코드에 넣지 않는다.
- 시작은 고정 크기 창으로 한다. 화면 확대·전체화면은 게임 좌표와 화면 좌표를 구분한 뒤 적용한다.
- 초반 그래픽은 색이 다른 직사각형, 공격 범위는 테두리로 표시한다. 그래픽 준비 때문에 동작 구현을 멈추지 않는다.

### 매 작업의 반복 순서

1. 오늘 추가할 행동 하나와 완료 조건을 적는다.
2. 현재 버전이 실행되는지 확인한다.
3. 필요한 최소 코드만 수정한다.
4. 새 행동과 기존 이동·공격·재시작을 직접 확인한다.
5. 성공한 코드를 Git에 커밋하고, 완료 기준을 모두 통과하면 단계 태그를 남긴다.

한 번에 여러 시스템을 완성하려 하지 않는다. 단계는 파일 하나를 뜻하지 않으며, 기존 파일에 기능을 누적하는 작업 단위다. 일정이 밀리면 장식·맵 크기·적 배치를 줄이고 다음 단계의 필수 기능을 확보한다.

## 4. 단계별 구현과 완료 기준

### 0단계 — 실행 기반

**목적:** 실행과 종료가 확실한 가장 작은 프로그램을 만든다.

구현: `main.py`에서 창 생성, 이벤트 처리, update, draw, 종료를 연결한다. 프레임 사이 경과 시간 `dt`를 계산하고 비정상적으로 긴 프레임은 제한한다. 입력은 눌렀을 때 1회 발생하는 입력과 누르고 있는 입력을 구분한다. 게임 내부 좌표·속도 단위를 정하고 화면에 테스트 사각형과 FPS를 표시한다.

완료 기준:

- [ ] 실행하면 창이 열리고 사각형이 표시된다.
- [ ] Esc와 창 닫기 모두 오류 없이 종료된다.
- [ ] 선택한 Python 인터프리터와 실행 명령을 README에 기록했다.

저장 지점: `v0.0-bootstrap`

### 1단계 — 이동과 점프

**목적:** 전투가 없어도 캐릭터를 조작할 수 있게 한다.

구현: 좌우 방향키 이동, C 2단 점프, 중력, 낙하 속도 제한, 직사각형 발판 충돌을 추가한다. 좌우 충돌과 상하 충돌을 나누어 처리한다. 착지하면 점프 횟수가 회복된다. 시각적인 캐릭터 크기와 실제 충돌 상자를 구분한다.

완료 기준:

- [ ] 좌우 이동과 방향 전환이 자연스럽다.
- [ ] 공중 점프는 한 번만 추가로 가능하다.
- [ ] 바닥·벽·발판 아래쪽에서 뚫림이나 끼임이 없다.
- [ ] 프레임 속도가 달라져도 이동 거리와 점프 높이가 크게 달라지지 않는다.

저장 지점: `v0.1-movement`

### 2단계 — 대시와 회피

**목적:** 공격을 붙이기 전에 이동·회피 규칙을 안정시킨다.

구현: Z 대시, 지상·공중 공유 2회 충전, 순차 충전 회복을 추가한다. 착지 없이도 충전이 회복된다. 대시 이동 시간과 시작 직후의 짧은 무적 시간을 각각 관리한다. 무적 상태는 색으로 표시하고, 임시 위험 구역을 만들어 피격 가능 여부를 확인한다.

대시 끝부분은 피격 가능해야 하며 연속 대시 사이에도 피격 공백이 있어야 한다. 대시 중 C 점프에 성공하면 대시 이동은 유지하되 무적은 종료한다. 이후 공격·무기 전환이 추가되면 해당 행동을 새로 시작할 때도 무적을 즉시 해제한다.

완료 기준:

- [ ] 세 번째 연속 대시는 충전이 없으면 실행되지 않는다.
- [ ] 공중에서도 충전이 순서대로 회복된다.
- [ ] 대시 시작·끝·연속 대시 사이의 무적 여부가 구분된다.
- [ ] 점프 성공 시 무적만 끝나고 필요한 이동은 유지된다.

저장 지점: `v0.2-dash`

### 3단계 — 기본 방망이와 공격 객체

**목적:** 공격 입력이 실제 타격으로 이어지는 최소 전투를 만든다.

구현: X 기본 방망이 지상 3타 콤보, 공중 단일 반복 공격을 만든다. 공격을 준비 STARTUP, 판정 ACTIVE, 후딜 RECOVERY로 나눈다. **공격 시작마다 Attack 객체를 생성**하고 ACTIVE 동안에만 판정을 활성화한다. 공격별 피해·스태거·판정 크기·지속 시간을 데이터로 분리한다.

정지한 연습 대상부터 배치한다. CombatSystem이 충돌·무적·피해·스태거를 처리하고 Attack은 이미 맞힌 대상을 기록한다. 기본 공격 한 번이 동일 대상을 매 프레임 타격하지 않게 한다. 동일 프레임에 여러 공격이 겹치는 경우의 1회 피해 규칙은 대상별로 처리하며, 명시적 다중 타격 예외는 나중에 추가한다.

공격 중 방향은 고정한다. 지상 공격 중 점프해도 시작한 지상 공격을 유지하고, 공중 공격 중 착지해도 해당 공중 공격을 유지한다.

완료 기준:

- [ ] 지상 3타와 공중 공격이 구분된다.
- [ ] 공격 판정은 ACTIVE에만 존재한다.
- [ ] 한 번의 공격으로 대상 HP가 의도한 횟수만 감소한다.
- [ ] 점프·착지가 진행 중인 공격 종류를 바꾸지 않는다.

저장 지점: `v0.3-basic-combat`

### 4단계 — 두 무기와 행동 연결

**목적:** 조화록의 핵심인 무기 전환 전투를 완성한다.

구현: 거대 방망이 지상 2타를 추가하고 Space로 기본·거대 방망이를 전환한다. 무기 차이는 공격 데이터로 표현한다. 전환 시 콤보 단계는 초기화하며 짧은 전환 무적을 적용한다. 공격 중 Space는 예약하고 공격 종료 시 한 번 실행한다. 대시 중에도 전환할 수 있다.

입력 규칙:

- X와 Z 동시 입력은 대시를 우선한다.
- RECOVERY에서 Z 대시로 후딜을 취소할 수 있다.
- STARTUP/ACTIVE의 대시 허용 여부는 이전 결정의 구체 값이 현재 요약에 없으므로 **구현 전 확정 항목**으로 둔다. 승인된 규칙을 확인하기 전에는 임시로 해당 구간의 대시를 막고, 한 설정값으로 교체할 수 있게 한다.
- 대시 중 공격·전환을 시작하면 기존 대시 무적을 끝낸다. 전환 무적은 별도 원인으로 관리하여 서로 잘못 삭제하거나 연장하지 않게 한다.

완료 기준:

- [ ] 두 무기의 타수·속도·범위 차이가 분명하다.
- [ ] 공격 중 전환 예약이 중복 실행되지 않는다.
- [ ] 후딜 대시 취소와 동시 입력 우선순위가 적용된다.
- [ ] 전환 후 이전 무기의 콤보와 공격 판정이 남지 않는다.

저장 지점: `v0.4-weapon-switch`

### 5단계 — 일반 적과 생존 전투

**목적:** 플레이어와 적이 서로 공격하고 죽는 전투를 완성한다.

구현: 일반 적 1종에 대기·접근·공격·경직·사망 상태를 붙인다. 적도 공격 시작마다 Attack을 생성한다. 적 AI는 행동을 선택하고 CombatSystem은 피해를 처리한다. 일반 적은 매 타격마다 멈추지 않고 스태거가 임계치에 도달했을 때 경직된다. 경직 종료 시 스태거를 0으로 초기화한다.

플레이어 HP, 피해 후 무적 시간, 사망을 추가한다. 사망하지 않은 일반 피격은 현재 공격·콤보를 유지한다. 피해 후 무적 시간은 확정된 대시 무적과 구분하는 조정값으로 둔다. 죽은 객체와 만료 Attack은 업데이트 도중 목록을 직접 바꾸지 않고 정리 단계에서 제거한다.

완료 기준:

- [ ] 적의 공격 준비를 보고 피하거나 반격할 수 있다.
- [ ] 일반 타격과 스태거 경직이 구분된다.
- [ ] 살아 있는 동안 피격으로 공격·콤보가 임의로 끊기지 않는다.
- [ ] 사망한 적이 다시 공격하거나 충돌하지 않는다.
- [ ] 플레이어가 죽으면 임시 시작 위치에서 전투를 다시 시작할 수 있다.

저장 지점: `v0.5-enemy-combat`

### 6단계 — 장승마을과 체크포인트

**목적:** 연습장을 실제 한 지역의 진행으로 바꾼다.

구현: 시작 구역 → 이동·점프 구역 → 일반 전투 구역 → 체크포인트 → 보스 입구를 잇는다. 카메라는 플레이어를 추적하되 맵 경계 밖으로 나가지 않는다. 월드 좌표로 충돌을 계산하고, 그릴 때만 카메라 위치를 뺀다. 상하 방향키는 필요한 상호작용에만 사용한다.

체크포인트에 재시작 위치를 기록한다. 사망 시 HP·속도·점프·대시·공격·전환 예약·Attack·적 상태를 정해진 규칙으로 초기화한다. 최소 버전은 일반 적을 초기 상태로 되돌리고, 보스 재도전 거리를 짧게 둔다. 게임 종료 후 진행 유지용 파일 저장은 필수 범위에 넣지 않는다.

완료 기준:

- [ ] 시작 지점부터 보스 입구까지 이동할 수 있다.
- [ ] 카메라 이동 중에도 발판·공격 판정이 맞는다.
- [ ] 체크포인트 활성화 후 죽으면 해당 위치에서 재시작한다.
- [ ] 재시작 직후 이전 공격이나 전환 예약이 실행되지 않는다.

저장 지점: `v0.6-village`

### 7단계 — 보스와 게임 종료

**목적:** 보스 격파라는 명확한 끝을 만든다.

구현: 보스 1종에 서로 구분되는 패턴 2개를 만든다. 예를 들어 가까운 거리의 방망이 휘두르기와 준비 동작이 긴 전방 돌진이다. 두 패턴은 구현 예시이며 외형·세계관에 따라 교체할 수 있다. 처음에는 순서대로 반복하고 안정화 후 거리 조건을 더한다.

보스는 일반 타격에도 패턴을 유지하며 HP만 감소한다. 스태거가 최대치에 도달하면 DOWN으로 전환하고, 다운 중 정상 피해를 받되 스태거는 누적하지 않는다. 기상 중에도 피해를 받을 수 있다. 다운 시 진행 중인 공격 판정 정리와 다음 패턴 복귀를 명시적으로 처리한다. 보스 HP UI, 전투 시작·패배 재도전·승리 화면을 연결한다.

완료 기준:

- [ ] 두 패턴에 식별 가능한 준비 동작과 회피 기회가 있다.
- [ ] 일반 타격으로 패턴이 매번 끊기지 않는다.
- [ ] 다운·기상·전투 복귀가 반복되어도 상태가 꼬이지 않는다.
- [ ] 보스에게 죽은 뒤 재도전하고, 격파 후 승리 화면에 도달한다.

저장 지점: `v0.7-complete-loop`

### 8단계 — 표현과 완성도

**목적:** 구현된 규칙을 플레이어가 보고 이해할 수 있게 한다.

## 5. 파일 구조도 점진적으로 확장하기

처음부터 아래 파일을 전부 만들 필요는 없다. 해당 기능을 추가하는 단계에서 분리한다.

| 도입 단계 | 파일/폴더 | 역할 |
| --- | --- | --- |
| 0 | `main.py`, `settings.py` | 실행·루프, 설정값 |
| 0 | `README.md`, `requirements.txt`, `.gitignore` | 실행 설명·의존성·Git 제외 항목 |
| 1 | `player.py`, `world.py` | 플레이어 동작, 발판과 충돌 |
| 3 | `attack.py`, `combat_system.py` | 공격 수명·판정, 충돌·무적·피해·스태거 |
| 4 | `weapon_data.py` | 무기별 공격 수치와 콤보 데이터 |
| 5 | `enemy.py` | 일반 적 AI와 상태 |
| 6 | `stage.py`, `camera.py`, `checkpoint.py` | 지역 배치·진행, 카메라, 재시작 정보 |
| 7 | `boss.py` | 보스 패턴·다운·기상 |
| 8 | `ui.py`, `assets/images/`, `assets/sounds/` | UI와 시청각 자료 |

플레이어의 이동·대시·공격은 독립 상태 변수로 관리하고, 행동별 별도 클래스를 대량으로 만들지 않는다. 파일 분리는 책임이 실제로 커졌을 때 진행한다. 객체끼리 서로 무조건 가져오는 순환 import를 피하고, 게임을 관리하는 쪽에서 참조를 전달한다.

권장 프레임 처리 순서: 입력 수집 → 행동·이동 갱신 → 지형 충돌 → Attack 위치·활성 상태 갱신 → 전투 판정 → 사망·만료 객체 정리 → 카메라 → 그리기. 같은 프레임의 충돌이 결정적으로 처리되도록 순서를 고정한다.

## 6. 단계마다 다시 확인할 조합

| 상황 | 확인할 결과 |

이 표는 매일 전부 반복하는 의무가 아니다. 수정한 기능과 연결되는 항목을 확인하고, 기능 동결 및 최종 제출 전에 전체를 점검한다.

## 7. 일정이 밀렸을 때의 판단

1. 움직임·전투·사망 재시작·승리는 유지한다.
2. 맵 길이, 일반 적 배치 수, 배경 장식과 연출을 줄인다.
3. 보스는 1종·2패턴, 무기는 기본·거대 방망이 범위를 유지한다.
4. 기능 동결 이후에는 새 시스템을 추가하지 않는다.
5. 단계 완료 기준을 통과하지 못하면 다음 기능과 섞지 말고 원인을 먼저 좁힌다.

## 9. 현재 출발점

이 문서는 구현 계획이며 실제 게임 코드의 완료를 의미하지 않는다. 현재 대화에 게임 소스가 첨부되어 있지 않으므로 0단계부터 진행하는 기준으로 작성했다. 기존 코드가 있다면 완료 기준을 대조하여 통과한 단계는 건너뛴다.
